# Minimal Core contract

1. A Host observes an explicit User request and supplies an attestation bound to its ingress identity, exact request digest, Session ID, expiry, and mode. Core checks these fields and exclusively consumes the ingress identity before creating a Session. Clarification and internal decisions cannot start another Session. A missing/ambiguous specification remains in the same Session; Worker execution waits for a ready frozen specification.
2. A Session owns one frozen specification, current Workflow, Run number, Attempt count, budget, checkpoint references, current Review/Decision, and terminal status. A workflow revision starts a new Run in the same Session. An Attempt is one Worker execution plus review boundary.
3. A Skill declares input type, output type, and capability. A Workflow consists of ordered stages with stable IDs, skill IDs, worker capability and criteria. The Core checks types, capability, artifact lineage, budget and legal transitions; it never interprets domain specific types. Frontier may propose candidate Skills with a new Workflow. Candidate Skills are promoted only after a matching artifact passes an independent Review in an ACTUAL Session. A successful workflow can be stored and reused for a matching goal, requirements, criteria and input type by another Frontier.
4. Host authorizes a declared `CapabilityRequest` with a sandbox root and named effects. Automatic effects are restricted to project-local paths and explicitly allowed effects; global install, credentials, account connection, paid API, upload, or elevated permission require separate Host authorization. The Core cannot turn denial into permission.
5. Worker returns bytes and an output type, which Core hashes and checkpoints. Reviewer receives that exact artifact, criteria and lineage. Frontier sees the Review and chooses `CONTINUE`, `RETRY`, `RESTART`, `REWORKFLOW`, `ACCEPT`, or `STOP`. `RESTART` retains only valid upstream checkpoints and starts at a named stage. `REWORKFLOW` must supply a new valid Workflow and likewise invalidates downstream checkpoints.
6. Transient by default. Durable: request/spec, current Workflow, verified checkpoints, current failure artifact, corresponding Review and Decision, terminal output, minimal history. Core does not store raw model prompts or routine stdout. Artifacts shared across models are a transport contract even when not promoted to checkpoints.
7. Budget exhaustion becomes `ABORT`; an adapter failure can be reconciled to `FAILED`. A final PASS enters `INTERNAL_ACCEPT`; only an exact accepted Artifact and a Host presentation receipt can make it `DELIVERED`. Those three states are terminal. A persisted `WORKER_IN_FLIGHT`, `REVIEW_IN_FLIGHT`, or `FRONTIER_IN_FLIGHT` cannot be automatically replayed after interruption. Explicit reconciliation closes with external evidence, never by blindly reissuing a call.

The historic `core-v1.0.0` actual C1–C5 proof demonstrates its original bounded loop. This branch's deterministic tests check the new contract; production 3D regression, actual low-model quality gain, and Blender/Video validation need real host and tool access in a later environment.
